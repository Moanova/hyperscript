# TSK33 — Panneau latéral des filtres (Journey + Agent) reporté dans la vue « Journeys »

- **Statut** : Review (20-11-2026) ; dépend de #TSK31 (Done). TSK32 dépend désormais de #TSK33.
- **Origine** : demande TSC séance 10 (tâche secondaire avant TSK32) — puisqu'un panneau latéral existe dans la vue « Relationships » (filtres Journey + Agent + liste des blocs), le reporter dans la vue « Journeys » ; le panneau doit être le même, mais **toute la partie qui liste les blocs (pour suivre les relations) doit être vide** dans « Journeys ».

## Analyse

- Le panneau n'existe que dans `RelationshipsWorkspace._build_ui` (`src/ui/views/relationships_workspace.py:323-374`) : `QSplitter` horizontal = vue matrice + panneau `QWidget` fixe (`relationships_view_panel_width_px` = 260, `SIDE_PANEL_STYLESHEET`) avec label + `journey_combo`, label + `agent_combo`, séparateur (`_SEPARATOR_HEIGHT`, `grid_major_color`), label « Blocks » + `block_list` (ascenseur vertical toujours visible, TSK31 3.2). Le pin de la fente du splitter au resize est dans `RelationshipsWorkspace.resizeEvent` (`:505`).
- `JourneysWorkspace` est un `QGraphicsView` nu, posé directement dans `journeys_page` (`src/ui/main_window.py:591-593`) : aucun splitter ni panneau.
- L'état des filtres est déjà centralisé dans `MainWindow` (`journey_filter_active`, `agent_filter_agent_id`) et poussé vers les workspaces (`_set_journey_filter_active` `:881-889`, `_set_agent_filter` `:910-919`) + menus Display. Le panneau « Relationships » émet `journey_filter_requested(object)` / `agent_filter_requested(object)` / `anchor_block_selected(int)` (TSK30 4.1).
- **Gap constaté** : après un CRUD agent (`main_window.py:944, 964, 978, 1017, 1072`), seul `_rebuild_agent_menu()` est appelé — le combo Agent du panneau « Relationships » n'est pas resync (périmé jusqu'au prochain `refresh()`). À corriger dans TSK33 via un resync des deux panneaux.

## Décisions actées (séance 10, TSC)

1. Le panneau des filtres est **le même widget** dans les deux vues : extraction en `FiltersSidePanel(QWidget)` (`src/ui/widgets/filters_side_panel.py`) avec option `show_block_list: bool` — séparateur + label « Blocks » + `block_list` affichés **seulement si `show_block_list=True`** ; dans « Journeys » (`show_block_list=False`) la partie liste est absente (zone vide sous les filtres).
2. Le splitter de la page « Journeys » est posé au niveau de `journeys_page` dans `_init_workspace` via `SidePanelSplitter` (même classe que « Relationships ») : le `JourneysWorkspace` reste inchangé (tous ses handlers souris), le panneau est un widget frère ; fente calée sur la largeur du panneau au resize (pattern TSK31 3.2).
3. Câblage identique dans les deux vues : choisir un parcours dans le panneau = **activation (FN026) + filtre (FN029)**, comme « Display > Journey » (décision TSK30 4.1) ; filtre agent → `_set_agent_filter`. Les setters de `MainWindow` poussent l'état vers **les deux panneaux** (combos toujours synchronisés avec le menu Display et entre vues).
4. `_resync_relationships_panel` → `_resync_filter_panels()` : resync des **deux** panneaux, appelé à chaque CRUD parcours **et agent** (corrige le gap ci-dessus).
5. Largeur de panneau partagée : nouvelle clé config `side_panel_width_px` = 260 (repli sur `relationships_view_panel_width_px`).
